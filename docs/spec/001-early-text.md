# 001：提早辨識文字與同幀呈現

狀態：DRAFT。建立：2026-10-21；更新：2026-10-22。
工作：[G3／#4](https://github.com/wicanr2/dark-queen-of-krynn-cht/issues/4)。
使用者要求在英文繪出之前攔截，避免英文閃現後才覆繪中文。
本規格已有初始角色管理選單的定位與隔離原型，首段劇情入口另見研究 004，尚未達到正式接入的 READY 條件。

## 證據身分

- 原版輸入、版本與雜湊見 [001 輸入基線](../re/001-input-baseline.md)。
- IDA Pro 9.4；MZ 載入基底為 IDA linear `0x10000`。
- dosgolem `f79eab6db8c64a524a06535e53e5d32b0bbcf7c8`，Go 1.24.13。
- 載入後 resident 的原版執行期基底為 `0110:0000`。
  本輪用三處 32-byte RAM／原始檔對照驗證 `IDA linear = runtime linear + 0xEF00`。
  這個公式只適用目前已核對的 resident，不外推動態載入區。
- 原始 `.i64` 在 `workplace/ida/dqk.i64`，各次查詢在一次性副本上執行。
  `tools/ida_probe.py`、`ida_inspect.py` 保留原始名稱、bytes 與 xref。

## 繪製前事件

在 `1212:03A0` 第一條指令之前，本輪主選單觀察到：

| 位置 | 本輪已證實的內容 |
|---|---|
| `SS:SP+4` | Y，原版像素 |
| `SS:SP+6` | X，原版像素 |
| `SS:SP+8` | 本輪顏色參數；高／低半位元組分別對應背景／前景的規則仍需更多狀態核對 |
| `SS:SP+10`、`SS:SP+12` | 字串 offset、segment；本輪完整選單字串是 NUL 結尾 ASCII |

## 原型與證據範圍

工具：[early_text_probe.go](../../tools/early_text_probe.go)、
[early_text_preview.py](../../tools/early_text_preview.py)。原型不修改 guest 暫存器、記憶體或規則。

2. 成對執行不掛觀測的控制組與只讀觀測組。
3. 在主選單建立期間，每 2,000 道指令記錄一幀，共 500 幀。
4. 兩側在 `#246M` 的暫存器、1 MiB RAM、原版色號與色盤相同。
5. 以繪製前事件及獨立 TSV 合成 16／20 像素圓體原型，保留原版按鈕位置。

收據：`workplace/probe/early-control/trace.json`、`early-observe/trace.json`；
預覽與報告：`early-observe/preview/`。快照 SHA-256：
`8a26ffb38cc507a13be146f5ca43571665be6308496623b28e11d6349b5c434e`。

這些原型證明有提早觀測完整選單字串的接點。離線合成不能單獨證明正式 GUI 不閃爍。

其色號畫面相同，但與這個原型分支的完整記憶體不同，不宣稱兩者整機同狀態。

## 實際視窗的窄範圍驗證

[early_text_live.go](../../tools/early_text_live.go) 是另一個 DRAFT 探針。
以 Ebiten 2.9.9、Xvfb 與軟體 OpenGL 實際開窗，從相同正常入口快照及一般 `p` 按鍵接續。
它在 `1212:03A0` 只讀取原文字串，隨即登記已辨識的選單文字。
每次 Draw 先把原版背景、原文字遮罩及中文字合成完整 640×400 貼圖，再一次提交。
不等待繪製後的畫面辨識，也不延後一幀才補上中文。

|---|---|

| RAM SHA-256 | `e06582277263a7f79e77d061a44f20bd3edd0ab986ee75e29849f26af9be0a8b` |
| 實際提交畫格 | 中文組 27 幀、原文組 26 幀；逐幀 GPU 讀回與各自原子合成輸入完全相同 |
| 本輪視覺抽驗 | 12 項已辨識的選單標籤未見先露出英文；原版標題、PLAY 等未處理字串仍保留英文 |

收據：`workplace/probe/live-zh/receipt.json`、`live-en/receipt.json`、
`live-zh/comparison.json`，逐幀 PNG 同目錄。中文收據 SHA-256：
`2bf332d1d8929bdfcdbe356603bdde53715d966ccdc59cf5f7282ff73d811165`；
原文收據：`7f583f9c8bad3f469fde54d8c7c8a3f3cb949305af2b4a7c084e45d5477ae3e3`。

再以 `-fine` 把文字建立期間細分為每 2,000 道指令一次實際 Draw，完成 560 個提交畫格，
其中 500 個涵蓋 `#241M` 至 `#242M`。最終 guest 狀態及 12 個事件仍與原文控制組相同。
記憶體事件收據的 `oom`、`oom_kill` 皆為 0。收據 `workplace/probe/live-fine/receipt.json`

限制：這是初次建立選單的視窗探針，未驗證互動返回、清除、捲動或存讀檔。
建立中的原版背景尚未完成，中文可能先出現在未畫好的按鈕上；不能把本輪結果宣稱為整個遊戲
已解決閃爍。正式接入仍須補齊背景及文字的生命週期，並驗證較慢更新下的呈現。

## 選單往返的呈現交易原型

2026-10-22 補充：[研究 003](../re/003-startup.md#2026-10-22讀取來源與返回的選單生命週期)
以一般 `p → l → e` 重播角色管理、讀取來源及返回。先前原型的事件表不清除，
確有在換畫面後保留舊標籤的結構缺口。本輪僅修正可丟棄原型，尚未接入正式程式。

`early_text_live.go -lifecycle` 的呈現契約如下：

- `1BB6:17B8` 的輸入返回值有效時，保留上一張完整合成畫面。
- 下一次 `1BB6:151F` 開始新批次時清除舊中文事件，保留期間照常收集提早攔截的文字。
- `1BB6:1585` 返回後，背景、英文字遮罩與中文在同一貼圖提交。
- 動作為 1 的 `0CEB:008E` 按鈕呼叫另成一組交易，以原始 far 返回位址及 SS:SP 成對結束。
  這涵蓋輸入處理內的反白重畫，不只包住整批繪製。
- 一般空閒批次不清除事件；未辨識的讀取來源標籤保留英文。
- 原始 EXE、入口 bytes 與正常快照不符即停止。原型不改 guest，未支援路徑不外推。

## 冷啟動鍵盤原型的補充邊界

[研究 003](../re/003-startup.md#2026-10-22冷啟動的實際鍵盤操作入口) 補上兩條真正 X11 輸入路徑。
由目前正式 TSV 衍生十二個標籤，從原版入口冷啟動，分別完成讀取取消返回，以及載入隊伍後
開始冒險、查驗欄輸入與退格。兩組視窗均正常關閉並保存檢查點，原版無覆繪重播狀態相同。

已證實：開始冒險的有效選擇索引為 10，此後到查驗題沒有下一批選單繪製返回。
因此舊有「選擇返回後等下一批完成」只適用已驗往返，不能外推這條離開路徑。
互動原型在選擇 10 後，等已核對的 `1212:03A0`、`%s`、原始 Y／X `8008／8068`
出現才清除舊中文及解除保留。數值不是像素座標；其他離開路徑未知。
空隊伍按開始冒險沒有有效選擇返回，不以殘留的選單表推定已切換。

這是可丟棄鍵盤原型，未進正式程式。只有十二項標籤及上述流程的證據，規格仍為 DRAFT。

## Shield 的語境限制

[研究 005](../re/005-translation-catalog.md#2026-10-22shield-的背包與法術書語境)
已在背包及法術書觀測到 Shield，均早於首字元 565 道指令；50 個原版狀態及 PNG 檢查點相同。
兩種文字共用 `%s` 及呼叫端返回位址 `0B72:027C`，不能以英文或返回位址全域選譯。
正式接入須辨識介面／欄位語境，分用「盾牌／魔法盾牌」，並驗清除與完整列表組句。
此階段未改譯表或接入中文，規格維持 DRAFT。

後續[列表及捲動證據](../re/005-translation-catalog.md#2026-10-22列表繪製捲動與-shield-字形對照)
