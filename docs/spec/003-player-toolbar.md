## 入口與資料

[player.sh](../../tools/player.sh) 提供 `prepare`、`build`、`run`，預設整合目錄為
`workplace/probe/player-current/`。資料準備由
[player_inputs.py](../../tools/player_inputs.py) 複製不可變來源，另產工具列字模與雜湊清單。
不載入研究快照或原版按鍵重播，不放入預設隊伍、測試狀態或答案。

```sh
bash tools/player.sh prepare
bash tools/player.sh build
bash tools/player.sh run
```

目前入口可直接啟動已建置的 `player-current`：

```sh
bash tools/player.sh run
```

`run` 需要目前桌面的 `DISPLAY`、既有 X11 存取權及合法原版。所有程式在離線 Docker 內執行。
原版目錄唯讀，存檔使用同批 `session/saves/`，截圖放 `session/screenshots/`，
前端視窗倍率與 HD 偏好分別放 `session/preferences.json` 的 `Scale`、`HD`。不覆寫原版來源存檔或研究主線快照。
工具列選擇不寫入 DOS 存檔，也不影響亂數、條件比較或遊戲資料識別。

呈現畫布固定為 960×600，中文及工具列維持原有 640×400 邏輯比例。
2 倍與 3 倍只改視窗尺寸為 640×400 與 960×600，視窗也可自由調整大小。
HD 開關獨立，縮放不會自動啟用或停用 HD。正常入口不逐幀寫圖、不保存完整研究收據。
主機端埠操作及呈現事件歷程有界保留，原始遊戲狀態及 VGA 現況保持。

- 原版開機以INT 33h AX=7／AX=8把範圍設為0..2559×0..1599，之後以AX=3輪詢，讀回的CX、DX各除以8當成320×200像素。dosgolem驅動回報CX＝保存X×2、DX＝保存Y；前端原本直接送像素，遊戲游標只走到應有距離的1/4與1/8，到不了底部選單。證據等級為強推論：依無頭oracle的INT 33h呼叫次數、範圍及七個位置的盾牌座標，沒有另行反組譯該除法。
- [整合入口](../../tools/early_text_live.go)的playerMouse改送遊戲單位：保存X＝像素×8÷2，保存Y＝像素×8。dosgolem驅動、原版資料、亂數與存檔不變；工具列與閱讀器的滑鼠仍只由前端處理。
- 無頭量測七個位置的盾牌左上角都在目標左上5像素，右下角(319,199)可達。Xvfb視窗九個指標位置的盾牌中心對準指標，點底部「開始遊戲」進入角色管理。[單元測試](../../tools/player_text_hd_test.go)固定換算與反算。
- 正常點選抽驗中，修正版9次有7次進入角色管理；1次因開場尚未接受Return而停在開場標誌，屬抽驗腳本時序；1次按鈕高亮後停住，當輪以強制結束收尾而沒有診斷，其後6次同條件重跑都沒有重現，列為未解釋的單次現象。Windows版另在Wine驗點選，非Windows實機。

## CONFORMED：防拷查驗自動填入

2026-10-31使用者要求把防拷密碼直接填在答案欄，選定「自動填入，自己按 Enter」。證據見[研究003](../re/003-startup.md#2026-10-31防拷查驗題庫與答案緩衝)。

- [player_quiz.go](../../tools/player_quiz.go)在啟動時從已核SHA的DQK.EXE解出60個答案。每幀只讀冷啟動提示層已核對的四個查驗文字；四個都完成且在畫面上時，讀`DS:C6F9`，內容屬於題庫答案且本次查驗尚未填過，才當一般鍵盤輸入送入。
- 原版出題、亂數、比較、記憶體與存檔不改；不自動按Enter。答錯後原版換題，新答案再填一次。查驗文字消失後重設，下次開始冒險再填。
- 中文與原文模式都會填入。正常視窗抽驗中，自動填入與手動輸入同一答案的查驗畫格及進城畫格逐像素相同；[單元測試](../../tools/player_quiz_test.go)核解碼規則、原版答案與失配拒絕。
- 作答進城後，底列的查驗「輸入」在原版翻頁或重寫該頁底列時撤除。條件只看原版顯存與翻頁，不依答案由誰輸入，見[規格005](005-render-owner.md#conformed查驗enter在原版換頁後退場)。
